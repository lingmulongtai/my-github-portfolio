# Projects site

静的サイト。ビルドツールなし、依存パッケージなし。`index.html` を開けばそのまま動きます。

`lingmulongtai` が所有する**全公開リポジトリ**を掲載します。フォーク・プロフィール・学習用リポジトリも含み、紹介文と画像を設定済みのリポジトリは35件です（2026年10月28日確認）。非公開リポジトリは取得・追加しません。

- 公開サイト: https://lingmulongtai.github.io/my-github-portfolio/
- リポジトリ: https://github.com/lingmulongtai/my-github-portfolio

```
.
├── index.html                      サイト本体（触らなくていい）
├── projects.json                   プロフィールと日英の紹介文
├── assets/projects/                各プロジェクトの生成背景画像とプロンプト
├── assets/site-previews/           サイト・アプリ画面のプレビューと出典
├── assets/hero-motion.js           ホーム背景の独立した波線・点の描画と動作制御
├── assets/page-motion.js           マーキーとマウス専用の文字・カーソル演出
├── data/github.json                公開時に自動生成（Git 管理外）
├── scripts/sync-github.mjs          全公開リポジトリの取得スクリプト
├── tests/                          カタログ・読み込み処理の回帰テスト
└── .github/workflows/               PR 検証と GitHub Pages 公開
```

## 1. まず書き換えるところ

`projects.json` の `profile` を自分の値に。

| キー | 中身 |
|---|---|
| `github` | GitHub のユーザー名。Pages の URL 推定にも使う |
| `links.github` / `links.linkedin` / `links.mail` | ヘッダーとフッターのリンク |
| `hero` | 大見出し。2行の配列。英大文字が一番きれいに出る |
| `location` / `role` / `intro` / `quote` / `about` | `{ "ja": "…", "en": "…" }` の形。英語を空にすると日本語が出る |

プロジェクト一覧は毎回 GitHub API から全ページを取得します。新しい公開リポジトリは、`projects.json` に書かなくても次の同期で追加されます。紹介文が未設定の場合は GitHub の説明・言語を使用します。

リポジトリを改名した場合は、`projects.json` の `repo`・`slug`・READMEリンクと、画像・プロンプトの識別子も新しい名前に揃えてください。上書き設定は `owner/name` の完全一致で紐付くため、旧名のままでは紹介文と画像が同期結果から外れます。

`projects.json` の `projects` 配列は、日英の紹介文・分類・おすすめ順の上書き設定です。おすすめ順では、ここにある公開プロジェクトを配列順で並べ、未設定の新規プロジェクトを更新順で末尾に追加します。削除済み・非公開のリポジトリは同期結果に含めません。閲覧者は人気順・コミット数順・更新順に切り替えられます。

| キー | 中身 |
|---|---|
| `slug` | リポジトリ名を小文字にした識別子。`#aerogrid-3d` のように個別リンクになる |
| `repo` | `owner/name`。**これが GitHub API との紐付けキー** |
| `size` | 以前のタイルサイズ指定を互換用に保持。現在の一覧ではすべて標準サイズで表示 |
| `filter` | `web` / `desktop` / `mobile` / `tools` / `hardware` / `research` / `docs` / `other` |
| `tag` / `summary` / `desc` | すべて `{ ja, en }`。確認できる用途・実装を記載する |
| `stack` | 技術タグ。言語自動判定とは別に、自分で見せたいものを書く |
| `image` | `assets/projects/<slug>.webp`。未指定の新規プロジェクトは単色背景 |
| `sitePreview` | サイト画面例の `image`、撮影元 `url`、種類 `kind`。URLが現在のリンク先と一致するときだけ表示 |
| `group` | トップレベルの `groups` の `id`。同じ製品のリポジトリをまとめる |
| `siteKind` | `app`（ブラウザで使う）/ `guide`（製品紹介）/ `page`（作品・サイト）。未指定は `page` |
| `showcase` | `false` の場合は「使えるサイト・アプリ」から除外する。このポートフォリオ自身や、現行版と公開URLを共有する旧リポジトリに使用 |
| `links.docs` | 仕様書などの任意リンク。空なら出ない |

star 数・全言語・ライセンス・最終プッシュ日時・全期間コミット数・年間コミットグラフ・**サイトのリンク**は GitHub から自動で取得します。ステータスも「公開」「フォーク」「アーカイブ」を実際の設定から表示し、進捗率や完成度は推定しません。

カード・詳細・イベントの更新日は、日本時間に変換して `JST` を付けて表示します。古いスナップショットなどで正確な日時がなく、UTC日付だけがある場合は `UTC` を付けます。更新順の並び替えは引き続き元の日時を使用します。

コミット数は `/commits?per_page=1` の最終ページから取得する、デフォルトブランチの全期間の履歴数（マージを含む）です。年間グラフは別の `/stats/commit_activity` から取得し、直近52週・マージを除く集計です。どちらも全貢献者・フォークを含むリポジトリ単位であり、GitHubプロフィールの個人貢献数とは一致しません。年間統計が処理中でも全期間の件数を取得できます。未取得の指標は0に置き換えず `—` で表示します。

GitHubはデフォルトブランチへのpush後に年間統計のキャッシュを再計算します。同期時に処理中（HTTP 202）のリポジトリがあれば、全件の取得後にその対象だけを最大4回、合計100秒待ちながら再取得します。待機後も処理中や取得できない場合は未取得のまま表示し、次回の同期で再び取得を試みます。

言語は各リポジトリの `/languages` に含まれる全言語を取得し、トップの集計エリアとカード・詳細に言語名を表示します。カード内はコード量の多い順です。言語の取得に失敗した場合だけ主言語を使用します。`stack` はフレームワークなどの紹介用タグとして別に保持します。

## 2. サイトのリンクについて

各リポジトリの **About → Website** 欄に URL を入れておくと、カードと詳細画面にサイトへのボタンが自動で出ます。`siteKind` に応じて「使ってみる」「紹介を見る」「サイトを見る」を表示し、44px以上の操作領域を確保します。リンクは `target="_blank"` と `rel="noopener"` で別タブに開く指定です（実際のタブ・ウィンドウの選択はブラウザの設定によります）。
空でも GitHub Pages が有効なら `https://<user>.github.io/<repo>/` を推定して出します。
手で指定したいときだけ `projects.json` の `links.site` に書けば、そちらが優先されます。

ホーム直後の「使えるサイト・アプリ」は、最初に「すべて」を表示し、ブラウザで使うものと紹介・作品を見るものに絞り込めます。サイトURLの重複を除き、Okuyukiの共通サイトも1件にまとめます。同じグループに異なるサイトが複数ある場合は、それぞれのリポジトリの名前と紹介文で区別します。写真部のVercelサイトは現行のKUAS Photography Clubとして上位に掲載します。新しい公開リポジトリのWebsite欄も次回同期で追加されます。実行できるブラウザアプリとして紹介する場合は `siteKind: "app"` を設定してください。

各カードには、公開サイトのスクリーンショットや公開リポジトリの開発版画像を、実際の画面例として掲載します。デモ・開発版・紹介ページはそれぞれ区別します。画像は撮影時点の静止画で、最新状態を示すライブ表示ではありません。撮影元と取得日は `assets/site-previews/README.md` を参照してください。リンク先が変更された場合や画像を読み込めない場合は、誤った画面を表示せず従来のイラストに戻ります。新規リポジトリのスクリーンショット生成は自動同期に含まれません。

製品のまとまりは `projects.json` の `groups` に `id`、`name`、日英の `summary` を定義し、各リポジトリの `group` で紐付けます。現在はOkuyukiの紹介サイト・Android・Quest・webOSと、CodexBarのAndroid・Windows・Mac版をそれぞれまとめています。「プロジェクト別」と「リポジトリ一覧」を切り替えられ、選択をブラウザに保存します。各グループは通常カードと同じ幅に、代表画像1枚・概要・個別リポジトリの行を表示します。各行から詳細を開け、画像・統計・言語の詳しい情報はリポジトリ一覧と詳細画面で確認できます。グループの位置は選んだカテゴリに一致するリポジトリのうち、選択した並び順で最上位のものに合わせ、グループ内も同じ順で並べます。統計は引き続きリポジトリ単位です。

グループに任意の `projectUrl` を設定すると、カードからGitHub Projectを開けます。CodexBarは[本人所有の共通Project](https://github.com/users/lingmulongtai/projects/3)へリンクします。`projectUrl` が未指定または無効な場合は、メンバーの紹介サイトへリンクします。GitHub Projectへの関連付けと、このサイトのグループ設定は別々に管理します。

## 3. デプロイ

1. 上のディレクトリ構成でファイルを配置して `main` に push
2. Settings → Pages → Source を **GitHub Actions** に設定
3. Actions タブで `Sync GitHub data and deploy Pages` を手動実行

以降は毎日 **03:17 / 07:17 JST** にデータ取得と公開を実行します。2回目は最初の実行が遅延・失敗した場合にも更新できる再実行枠です。`index.html`、`projects.json`、`assets/`、取得スクリプト、ワークフローを編集して `main` に push したときも実行されます。

GitHubのスケジュールは遅延・実行省略の可能性があり、公開リポジトリが60日間活動していない場合は自動停止します。そのため毎日の実行を絶対保証するものではありません。停止時はActionsからワークフローを再有効化してください。サイトに最終同期日時（JST）を表示し、36時間を超えたデータまたは同期日時不明のデータは「更新待ち」と表示します。[GitHubのスケジュール仕様](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

`data/github.json` は実行時に生成し、サイト本体と一緒に Pages へ公開します。自動更新でリポジトリへコミットする必要はありません。公開対象は `index.html`、`projects.json`、`data/github.json` と `assets/` です。

取得には標準の `GITHUB_TOKEN` を使うため、追加のシークレット設定は不要です。公開一覧を最後まで取得できない場合や0件の場合は公開を中止します。コミット集計が処理中・取得不能でも、そのプロジェクト自体は掲載します。

ローカルで同じデータを取得する場合は `node scripts/sync-github.mjs` を実行してください。API の利用制限を避けたい場合は、環境変数 `GH_TOKEN` に認証情報を渡せます。トークンをファイルやコミットに含めないでください。

検証は `node --test tests/*.test.mjs`、表示確認は `python -m http.server 4173 --bind 127.0.0.1` で行えます。PR と公開前にも同じテストを実行します。

## 4. データの読み込み順

1. `data/github.json`（Actions が作った `owner` / `syncedAt` / `projects` / `stats` を含むスナップショット）
2. なければブラウザから GitHub API で全公開リポジトリを取得（年間グラフ・全期間コミット数・全言語の集計は取得せず、言語は主言語だけを表示）
3. どちらも駄目なら `projects.json` の紹介文を表示し、統計は `—` とする

デモ用の数値は使用しません。詳細のイベント欄も取得済みの最終更新だけを表示します。

つまり `index.html` を単体でローカルで開いても、見た目の確認はできます。
`file://` で開くと `projects.json` の読み込みが CORS で弾かれるので、`index.html` 内の
`<script type="application/json" id="site-data">` に入っている予備データが使われます。
確認用にローカルサーバを立てるなら `python3 -m http.server` で十分です。

外部通信がブロックされた環境では「GitHub データ未取得」と表示します。

## カードの画像

公開35件の画像は、各プロジェクトの用途をもとにChatGPTの内蔵画像生成で個別に作ったコンセプトイラストです。実際の画面や製品の写真ではありません。プロフィールのイラストを画風の参照にし、黒い手描きの筆線と青緑・黄色のアクセントで揃えています。共通の画風と各画像の生成プロンプトは `assets/projects/prompts.json` に保存しています。Mac版 Mobile Connect と SAKURA AVENUE の画像も個別に生成し、実際に使用した全文プロンプトと参照画像を各項目に記録しています。

配信用画像は幅1280pxのWebPに最適化し、遅延読み込みを使用しています。絵全体を切り取らず表示し、タイトルとは独立した領域に置いて重なりを防ぎます。アクティビティ・About・フッターの挿絵は `assets/illustrations/`、そのプロンプトは同フォルダの `prompts.json` に保存しています。新規リポジトリの画像生成は自動同期に含まれません。画像を追加するときは `image` と予備の `site-data` を更新してください。

## 5. 操作

- ホーム左下の「背景の動きを止める」/「背景の動きを再生」… 背景アニメーションを切り替え。停止設定は同じブラウザの次回訪問にも保存します。
- ヘッダーの `Search` / `Ctrl+K`（Macは `⌘K`）… 検索（技術名でも引っかかる）
- カテゴリ … 選んだ種類だけを表示。スマートフォンではカテゴリを横にスワイプでき、言語を切り替えても選択を保持します。
- ホームの「すぐ使えるサイト」… ブラウザアプリや製品の紹介・作品サイトをまとめた入口へ移動します。
- プロジェクト別 / リポジトリ一覧 … 関連するリポジトリを製品ごとにまとめる表示と、全件を独立して並べる表示を切り替えます。カテゴリに該当するメンバーがないグループは表示しません。
- 並び順 … おすすめ順、人気順（スター数、同数ならフォーク数）、コミット数順（全期間）、更新順（プッシュ日時）を選択できます。未取得の値は最後、同値はおすすめ順で安定させます。選択はブラウザに保存し、言語を切り替えても保持します。詳細の前後移動と検索結果にも選んだ順番を反映します。
- 検索右上の `×` … 検索を閉じる。日本語入力の変換確定では詳細を開きません。
- 詳細を開いた状態で `←` `→` … 前後のプロジェクト
- `Esc` / カード外の背景をクリック … モーダルを閉じる
- `Tab` / `Shift+Tab` … 開いているモーダル内を移動
- 右上の `JA / EN` … 言語切り替え。選択は次回も保持される

スマートフォンでは主要な操作領域を44px以上にし、ホームにプロジェクト・自己紹介へのリンクを表示します。プロジェクト詳細は上部に前後移動と閉じる操作を固定し、閉じると一覧の元の位置へ戻ります。検索は表示中のキーボードに合わせた可視領域内に収まるよう調整します。タブレットではカードを2列で配置します。

ホームは画面の高さに合わせて引き伸ばさず、ヘッダー直下から紹介文・肖像・背景の停止ボタンを内容順に並べます。上下は16〜20pxの余白に留め、次のセクションまで大きな空白を設けません。

ホームの装飾は外部ライブラリを使わず、Canvasで青・黄色の短い波線と同じ太さの点を描画します。各波線は独立した周期と方向で動き、灰色のつなぎ線はありません。装飾は紹介文と分けた肖像の正方形領域にまとめ、淡い色面・波線・点の全体と余白が収まるよう縮小します。画面端で図形を切ったり、文字の周囲で波線を消したりせず、狭い画面では紹介文の下に構図全体を配置します。

スマートフォンではホームを短くタップすると波線が反応し、青と黄色の点が広がります。スクロール・長押し・複数指操作・リンクやボタンには反応させません。タッチ操作でマウス用のカーソルや文字変形を残さず、カードは押した瞬間に色とサイズで反応します。

OS・ブラウザの「動きを減らす」設定では静止画になります。背景とマーキーはそれぞれ画面外にある間、タブが非表示の間、検索・プロジェクトのモーダル表示中も停止します。背景の停止ボタンはマーキーにも適用します。描画は最大30fpsに制限し、画面配置に変化がないリサイズ通知ではCanvasを作り直しません。

## 6. AI に編集させるとき

`projects.json` だけ渡して「このプロジェクトを追加して」「説明を書き直して」と言えば済みます。
守ってほしいのは次の3点だけ:

- `slug` は重複させない（URL になる）
- `tag` / `summary` / `desc` は必ず `ja` と `en` の両方を書く
- `repo` は実在する `owner/name` にする（間違っていると数値が出ない）

README・実装で確認した内容を使い、フォークを独自開発と書いたり、未検証の機能を完成済みと書いたりしないでください。紹介文を編集した場合は `index.html` 内の `site-data` にも同じ JSON を反映すると、単体プレビューも一致します。
